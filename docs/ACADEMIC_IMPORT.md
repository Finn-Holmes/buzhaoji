# 教务网课表导入架构

## 用户流程

1. 选择学校后打开学校官网；学校未收录时填写学校官网地址，默认使用“自动识别”，也可以手动指定教务系统类型。
2. App 在受限 WebView 中打开学校网站，用户自行完成登录。
3. 用户打开本学期课表并主动点击“确认导入”。
4. 内置适配器在设备本地读取当前页面和同源 iframe，输出统一课程结构。
5. 用户在原生预览中修改或删除识别结果，确认信息正确。
6. 当前已有课程时选择覆盖或合并，然后校准学期第一周再保存。

图片 OCR 和表格文本导入始终保留为备用路径。

## 统一课程结构

适配器输出字段：课程名、教师、教室、星期、开始节次、结束节次和精确周次集合。学校目录负责把节次换算为该校真实起止时间。精确周次以 64 位掩码保存，因此可以正确表示 `1-5,8-10周` 等非连续安排。

## 适配层级

- 学校专用适配：处理该校特有 DOM、WebVPN 地址和作息时间。目前 UPC/强智已用真实页面验证。
- 教务系统适配：包含强智 `timetable/kbcontent`、正方 `kbgrid_table/timetable_con`、URP `class_div` 和青果“周次[节次]”矩阵等解析器；除 UPC 外仍需积累真实学校页面回归样本。
- 自动识别：未知学校依次尝试强智、正方、URP、青果和通用表格，不会因为学校目录没有预先标注供应商而停止。
- 通用表格适配：只接受至少五个星期表头，且课程块同时存在周次和节次；同时尝试读取页面中的节次时间，用于页面结构接近标准 HTML 表格的学校。
- 结构诊断：五种解析器全部失败后，只采集表格尺寸、星期表头数量、选择器和脱敏路径，不采集账号、课程正文、教师、教室、HTML 或 Cookie。
- 图片 OCR：先根据 OCR 坐标识别星期列、节次时间、课程块、周次和单双周；网格不完整时回退为文字校对。

新增学校通常只需登记官方登录地址、允许域名、教务系统类型和节次时间；只有页面结构特殊时才需要新解析器。

## 安全边界

- 用户名和密码只提交给学校网站，App 不注入读取登录字段的桥接代码。
- 只有用户明确确认后才执行内置解析脚本。
- WebView 只允许 HTTP(S) 与必要的 `about:` 页面，拒绝 `javascript:`、文件和自定义协议；统一认证、WebVPN 和跨域跳转仍可正常工作。
- 不允许网络下发任意 JavaScript。后续在线目录只发布经过审核和签名的声明式学校配置及版本化内置适配器编号。
- 课表 HTML 和识别结果不上传服务器。

## 扩展到多数学校的发布步骤

1. 已加入首批常用高校官网目录，并严格区分“已验证”和“自动识别 · 试验性”。
2. 收集失败页面的脱敏结构样本，按供应商补选择器变体和自动化回归夹具。
3. 对正方、URP、青果各补充至少两个脱敏真实页面样本测试。
4. 建立签名目录更新：公钥固定在 App，目录包含版本、有效期、配置摘要和适配器编号。
5. 上线“报告适配问题”，只上传用户主动选择的脱敏诊断，不上传登录字段或完整私人课表。
6. 真机验证统一认证、WebVPN、验证码、重定向、新窗口和系统 WebView 差异。

适配目标应按“可回归验证的学校数量”衡量，而不是声称一个宽松的万能解析器支持所有学校。
